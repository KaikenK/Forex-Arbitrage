# Reproducing the paper's results

Every result comes from one command; `python -m research.reproduce` runs them in order and
refuses any step whose prerequisite is not met. Run from the repository root (the folder
that contains `research/`). Decisions, rules and numbers are in `RESEARCH_TRACKER.md` §6.

```bash
python -m research.reproduce --list        # what exists, what is blocked and why
python -m research.reproduce --run h2h3    # one step
python -m research.reproduce --run all     # everything, in order, stopping at the first block
```

Laptop rule: steps marked *heavy* load price data or transformer models. Run them one at a
time and never while the live semantic service or backend is running.

## Inputs (not regenerated by these steps)

| Input | Where | How to obtain |
|---|---|---|
| ForexFactory calendar dump | `research/artifacts/forex_factory_calendar.csv` | acquired static file (see §6, 2026-08) |
| HistData M1, 4 majors, 2018–2025 | `%LOCALAPPDATA%\arbex\histdata` | `python -m research.fetch_histdata` |
| GDELT headlines 2018–2021 | `research/artifacts/gdelt_shards/` | `python -m research.gdelt_backfill --start 2018-01-01 --end 2022-01-01` (resumable) |
| Live recordings (H6b) | `%LOCALAPPDATA%\arbex\recordings` | backend in live mode (`RUN_STEPS.md`, "Live semantic stack") |

## Paper item → step → artifact

| Paper item | Step(s) | Artifact (`research/artifacts/`) | Gate |
|---|---|---|---|
| Calendar store (all scheduled-event results) | `calendar` | `calendar_events.parquet` | dump present |
| Positive control (ABDV replication; record + Option A check + robustness) | `positive_control` | `positive_control.json` | calendar, HistData |
| R1 re-run, USD/INR and EUR/USD daily (+ pandemic window dropped) | `r1_usdinr`, `r1_usdinr_excl_window`, `r1_eurusd`, `r1_eurusd_excl_window` | `r1_rerun.json` (appended) | calendar |
| R1 as originally reported | `r1_legacy` | stdout | pre-fix calendar backup |
| H2 category CARs, H3 half-lives | `h2h3` | `h2h3.json` | calendar, HistData |
| GDELT feature table (descriptive) | `features` | `features.parquet` (+ manifest) | shards |
| News-sample coverage (frozen sample) | `freeze` | `gdelt_sample_freeze.json` | at/after 2026-11-02 00:00 IST (DEVIATION 1) |
| Archive scores | `score_dedup`, `score_lexicon`, `score_finbert`, `score_embed` | `archive_scores/<stage>/` | frozen sample; later stages need `dedup` |
| H1 novelty vs sentiment (decides on sentence-transformer) | `h1_primary`, `h1_tfidf`, `h1_hashing`, `h1_decide` | `h1_results.json` | scores stamped with the freeze hash |
| H5 currency sentiment factor (same-day, explanatory) | `h5_lexicon`, `h5_finbert`, `h5_decide` | `h5_results.json` | scores stamped with the freeze hash |
| H6 currency bias forecast + horizon | `h6` | `h6_results.json`, `h6_horizon.json` | scores stamped with the freeze hash |
| H6b prospective ranking (exploratory) | `h6b` | `h6b_results.json` | after 2026-11-05 00:00 IST |

After `h6`, copy `h6_horizon.json` to `services/semantic/artifacts/` (or point
`SEMANTIC_CURRENCY_BIAS_HORIZON` at it) so the live currency index reports the measured horizon.

## What the scripts enforce on their own

The gates above duplicate checks the scripts already make, so a step cannot be run out of
order by calling it directly: `freeze_gdelt_sample` refuses before the cutoff and never
overwrites a freeze; `score_archive` reads only the frozen shards; `run_h1`, `run_h5` and
`run_h6` refuse without the freeze, without scores carrying its hash, or with any
protocol clause unset; `run_h6b` refuses before its window closes and drops opportunities
after it.
